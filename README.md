# ✈️ TripMate AI

A multi-agent travel planner built with **LangGraph**, **Groq**, **Tavily** and **FastAPI**.
Tell it where you want to go and it plans the whole trip in one chat: flights, real hotel names, trains and metro, weather, a day-by-day itinerary on a map, a budget, and ready-to-open booking links.

**🔴 Live demo:[**(https://trip-mate-ueab.onrender.com/)](https://trip-mate-ueab.onrender.com/)
**💻 Source:** https://github.com/DibyanshYadav/TRIP_MATE

> TripMate cannot book anything. It builds search links, so always confirm prices and availability on the booking site.

---

## What it does

- **Flights**: live route and status data, plus Google Flights, Skyscanner and Kayak links
- **Hotels**: real hotel names with area, price and nearest metro, taken from web search and verified in code so the model cannot invent hotels
- **Trains and local transport**: respects preferences like "3AC trains" or "I want metro"
- **Itinerary and map**: day-wise plan with colour-coded pins on an OpenStreetMap map
- **Budget**: itemised cost table, with live currency conversion
- **Weather and packing tips**
- **Live progress**: the UI streams each agent step ("Searching flights", "Finding hotels", ...) while the plan is built
- **Memory**: remembers trip facts (dates, budget, preferences) across the conversation, so follow-ups like "make it cheaper" work
- **Export**: copy the plan or download it as a PDF

## How it works

```
User message
     |
     v
 prepare  --> extracts trip facts (dates, budget, preferences) + summarizes old chat
     |
     v
  chat  <------------------------+
     |  (LLM decides which tools to call)
     v                           |
  tools  -------- results -------+
     |
     +-- flight_agent                 live flight data
     +-- hotel_agent                  Tavily search -> LLM extraction -> name verification
     +-- weather_agent                destination weather
     +-- train_local_transport_agent  trains, metro, buses
     +-- itineary_agent               day-by-day plan + map places
     +-- budget_calculator_agent      cost table
     +-- currency_converter_agent     live exchange rates
     +-- travel_links_agent           booking links built in code
     |
     v
 FastAPI (SSE stream) --> custom HTML/CSS/JS frontend (Leaflet map)
```

**Design decisions worth knowing**

- **No invented links or hotels.** Booking links are generated by code, and every hotel name must appear in the search text before it is shown.
- **Code fallbacks.** If the model forgets to call the links or itinerary tools, the backend builds them anyway, so the map and links appear every time.
- **Token-aware.** Small model for extraction and summaries, large model for planning and chat. Tool outputs are trimmed before they reach the LLM.
- **Persistent threads.** LangGraph checkpointer on Postgres when `DATABASE_URL` is set, in-memory otherwise.

## Tech stack

| Layer | Tools |
|---|---|
| Agent framework | LangGraph, LangChain |
| LLMs | Groq (gpt-oss-120b for planning, llama-3.1-8b-instant for extraction) |
| Search | Tavily |
| Flights / FX | AviationStack, freecurrencyapi (with open.er-api.com fallback) |
| Backend | FastAPI, Server-Sent Events |
| Frontend | Vanilla HTML/CSS/JS, Leaflet, OpenStreetMap, marked, html2pdf |
| Storage | Postgres (optional) |
| Deploy | Docker, Hugging Face Spaces |

## Run it locally

**1. Create a `.env` file**

```env
GROQ_API_KEY=your_key
TAVILY_API_KEY=your_key
AVIATIONSTACK_API_KEY=your_key
CURRENCY_API_KEY=your_key
GEO_CONTACT_EMAIL=you@example.com
# optional, for saved chats:
# DATABASE_URL=postgresql://user:pass@localhost:5432/tripmate
```

**2a. With Docker** (includes Postgres)

```bash
docker compose up --build
```

**2b. Without Docker**

```bash
pip install -r requirements.txt
python app.py
```

Open http://localhost:8000 (health check: `/health`).

## Deploy to Hugging Face Spaces

1. Create a new Space with the **Docker** SDK.
2. Add the keys above under **Settings → Variables and secrets**.
3. Push this repo to the Space. The header at the top of this README tells Hugging Face how to run it.

## Known limitations

- Flight data is **live status, not fares**. Fare ranges are rough, and the booking links show real prices.
- Hotel prices come from web snippets and may be outdated or missing.
- Free hosting means the app can be slow on the first request after a long idle period.

## Roadmap
